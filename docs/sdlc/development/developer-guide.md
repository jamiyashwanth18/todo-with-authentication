<!-- sdlc:auto:start overview -->
TODO with authentication is a monorepo generated by the Quorq AI SDLC platform. The intended product is a to-do app with sign-up, sign-in and per-user tasks. It holds two applications. `frontend/` is a Vite 6 + React 19 + TypeScript SPA styled with Tailwind CSS v4 and routed with react-router-dom v7. According to its README, its screens still render seeded sample data. `backend/` is a FastAPI 0.115 service using SQLAlchemy 2 and Pydantic 2. It defaults to a local SQLite file (`sqlite:///./app.db`) and can be pointed at PostgreSQL 16 through `DATABASE_URL`. The backend is still a scaffold: its only route is `GET /health`, it defines no models yet, and the routers package is empty. Tables are created from the models at startup with `create_all`, and there are no migrations. `frontend/src/lib/api.ts` provides `apiFetch`, which reads its base URL from `VITE_API_BASE_URL` and sends a bearer token. That token comes from `localStorage` or falls back to `VITE_API_SECRET_KEY`. This is the intended seam for wiring screens to the API.

<!-- sdlc:auto:start prerequisites -->
- Node.js with npm (for frontend/)
- Python 3.12 with pip (the version used by backend/Dockerfile)
- Docker with Docker Compose (optional: to run PostgreSQL 16 via docker-compose.yml or to build the backend image)
- Chromium for Playwright (installed with `npm run test:e2e:install`, only needed for end-to-end tests)

<!-- sdlc:auto:start setup -->
1. cd backend
2. python -m venv .venv && . .venv/bin/activate  # playwright.config.ts expects backend dependencies in backend/.venv
3. pip install -r requirements.txt
4. uvicorn app.main:app --reload  # serves the API on http://localhost:8000 using SQLite ./app.db by default
5. In a second terminal: cd frontend
6. npm install
7. npm run dev  # Vite dev server; the backend's default CORS allows http://localhost:5173
8. Optional, to use PostgreSQL instead of SQLite: docker compose up -d db (from the repo root), then start the backend with DATABASE_URL set to the compose database (user/password/db are all `app` on localhost:5432; psycopg 3 is the installed driver)
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Frontend imports use the `@/` alias for `frontend/src` (configured in vite.config.ts and tsconfig.json).
- TypeScript runs in `strict` mode but with `noImplicitAny` and `strictNullChecks` disabled. `vite build` does not typecheck, so run `npm run typecheck` separately.
- Component tests live beside their components in `src/` as `*.test.ts(x)` or `*.spec.ts(x)` (Vitest with jsdom and globals). Playwright specs live in `frontend/e2e/`, which Vitest excludes.
- All API calls go through `apiFetch` in `src/lib/api.ts`. It joins paths onto `API_BASE_URL` with exactly one slash and sends `Authorization: Bearer <session token or VITE_API_SECRET_KEY>`. A login flow is expected to store the token returned by `/auth/login` with `setSessionToken`.
- Backend models inherit `Base` from `app/database.py` and go in `app/models.py`. `main.py` imports models so `create_all` registers the tables at startup. There are no Alembic migrations yet.
- Database access uses the request-scoped `get_db` dependency, one session per request.
- Generated backend routes are stubs that return the typed `StubResponse` placeholder until they are implemented, with one router per component under `app/routers/`.
- Configuration comes from env vars read in code: `DATABASE_URL` and `ALLOWED_ORIGINS` (comma-separated CORS origins, defaulting to localhost:5173) on the backend, and `VITE_API_BASE_URL` and `VITE_API_SECRET_KEY` on the frontend.
- Python linting and formatting use Ruff; frontend linting and formatting use ESLint and Prettier (eslint-config-prettier).

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| The frontend fails to start or build with an error resolving `@/App`. | `main.tsx` imports `@/App`, and frontend/README.md describes `src/App.tsx`, `src/screens/` and `src/lib/brand.ts`. None of these appear in this repository's file tree. Restore or create `src/App.tsx` (the route table) before running the app. |
| Browser requests from the SPA to the API are blocked by CORS. | By default the backend only allows http://localhost:5173 and http://127.0.0.1:5173. If the frontend runs on another origin, set `ALLOWED_ORIGINS` (comma-separated) before starting uvicorn. |
| `pytest` fails with `ModuleNotFoundError: No module named 'app'`. | Run pytest from inside `backend/`, where pytest.ini sets `pythonpath = .`. |
| `npm run test:e2e` cannot start the backend web server. | Playwright launches `../backend/.venv/bin/python`. Create backend/.venv and run `pip install -r requirements.txt` inside it first, or set `E2E_BASE_URL` to an already running app. |
| Playwright reports that the browser executable is missing, or Chromium crashes in a container. | Run `npm run test:e2e:install`. The config already passes `--disable-dev-shm-usage` to work around the small /dev/shm in containers. |
| The backend fails at startup when `DATABASE_URL` points to PostgreSQL. | Make sure the database is running (`docker compose up -d db`, then wait for its healthcheck). Tables are created on startup, so connection errors appear when the app starts, not when it is imported. Unset `DATABASE_URL` to fall back to SQLite. |
| `npm run build` succeeds but `npm run typecheck` reports errors. | This is expected: the build does not typecheck. The frontend README notes that generated screens often use untyped `useState({})`; add types to fix these errors. |
| An API call returns `not_implemented` placeholders. | Generated routes return `StubResponse` until implemented. Currently only `GET /health` has real behaviour. |
<!-- sdlc:auto:end troubleshooting -->
